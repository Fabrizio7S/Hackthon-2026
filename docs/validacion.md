# Validación

## Estado actual
Base técnica inicializada. Comprobar TypeScript con npm run typecheck y generar bundles con npm run export. No hay pruebas automatizadas de funciones del producto. La evidencia concreta y los límites de esta inicialización se registran en T00.1.

## Al implementar
- Registrar comandos reales, resultados observados y entorno en cada ficha.
- Añadir pruebas automatizadas que protejan reglas o transiciones relevantes, sin pruebas triviales solo para aumentar cantidad.
- Verificar móvil y volver; registrar dispositivo/emulador y límites si no está disponible.
- Usar dos cuentas para invitación y ayuda; probar permisos con cuenta ajena cuando corresponda.
- Abrir llamada o WhatsApp solo demuestra contacto, no prestación completada.
- Comprobar coherencia entre lista, mapa, detalle e historial incluidos.
- Offline requiere pérdida/recuperación real de conexión, reapertura, reintentos y ausencia de duplicados. Un indicador simulado no basta.
- Validar tres clics desde el punto acordado, tutorial y accesibilidad según Q08.
- Identificar datos de ejemplo, simulaciones y resultados no comprobados.

## Evidencia
Registrar criterio, pasos o comando, resultado y límite. Si no se pudo comprobar, explicar qué falta. Guardar solo evidencia pertinente y sin datos sensibles.

## Revisión de contexto
Una sesión nueva debe poder responder desde los archivos: qué producto es, acuerdos y dudas, etapa y grupo activo, stack confirmado, comandos existentes, siguiente paso y límites de Git.
Leer respuestas en documentos es revisión documental; no equivale a probar un agente nuevo ni la app.
